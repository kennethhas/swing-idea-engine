## Data-source status (requested check)

**The repos contain no market data.** `swing-idea-engine` holds only the skill itself
(`.claude/skills/swing-idea-engine/`); `claude-trading-skills` has no `reports/` directory and no
cached snapshots. Nothing was stale — there was nothing there to be stale.

**The skill's built-in feeds are blocked by this environment's network policy:**
- `zone_scanner.py` / `squeeze_scan.py` / `regime_gate.py` fetch Yahoo (`query1/2.finance.yahoo.com`) → **403 at the egress proxy**.
- `data_sources.py`'s corroborating feed (CNBC) → also blocked. So were stooq, nasdaq and alphavantage.

**Workaround used this run:** priced everything through the session's sanctioned MCP connectors —
**Massive** (`/v2/aggs` daily OHLC, 499-bar cap, ~3 requests/min) for bars, written to CSV and fed to
the skill's own scripts via `--csv`; **FMP** as the independent cross-feed and earnings calendar.
`regime_gate.py` has no `--csv` option, so its posture formulas were applied to the same data in SQL.

**Recommended refresh / fixes**
1. Add `--csv` support to `regime_gate.py` so Step 0 runs without network access.
2. Point `data_sources.py` at a reachable second feed (FMP works) instead of CNBC.
3. Allowlist a market-data host, or add an MCP-backed fetch path to the scanners, so the skill
   is not dependent on Yahoo being reachable.
4. The 499-bar cap limits weekly context to ~2 years; page the Massive endpoint by date range to
   restore the skill's intended 5-year weekly scan.
